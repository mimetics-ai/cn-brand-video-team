# 交付证据卡 · 结构化缺陷与追溯链判据（v1.12.0–v1.14.0）

> 来源：2026-11-13 两条只读考察（见 `docs/benchmark_canvas_gates_20261113.md`）。
> 一句话：**「做完了」和「验得住」是两件事**。产物齐备、时间线拼好、计数报 0 errors，
> 仍可能因为追溯链断开而不可交付。这张卡把「验得住」写成可勾选、可复算的对象。
>
> 与 v1.9.0 的关系：资产台账（`tools/asset_ledger.md`）管「素材有没有身份」，
> 本卡管「结论有没有证据、能不能复算、返工后作没作废」。
>
> v1.13.0 增补第九节：判据本身没错、但**输入被验证动作污染**或**检查器读不懂写法**时，
> 同样会得出假结论。三条底线合起来才算「验得住」。
>
> v1.14.0 增补 9.3 与第十节：这一轮验得住，不等于换一代判据、换一条通道还验得住。
> 历代判据是否零漂移、FAIL 是否仍是 FAIL、每轮必跑项是否被清单强制、取值层有没有读错字段——
> 这四问不回答，「验得住」只在单轮成立。

---

## 一、什么时候用

**强制**：检查点 B 之后、Phase 4 宣称「已交付」之前；凡是**生成档 / 叙事片 / 短剧档**都要过。
纯文字交付（结构卡、初稿）可省。
**触发重跑**：分镜表、脚本、素材、提示词、时间线、成本台账任一处改动 ⇒ 本卡结论立即作废，重跑后才恢复。

---

## 二、缺陷必须写成对象，不许只报总数

每一条不通过项写成一条 `issue`，七个字段缺一不可：

```json
{
  "code": "SHOT_MEDIA_MISSING",
  "severity": "error",
  "scope": "shot",
  "message": "镜头 s04 尚无可追溯的图片或视频节点。",
  "evidence": { "mediaNodeIds": [], "shotId": "s04" },
  "suggestedAction": "生成或绑定代表性分镜/视频，并保留 shotId 关系。",
  "requiresVisualReview": true
}
```

| 字段 | 要求 |
|---|---|
| `code` | 稳定枚举名，不写自由文本；同一类缺陷跨轮次用同一个 code |
| `severity` | `error`（阻断）／`warning`（可放行但须记录）／`info`（提示） |
| `scope` | `shot`／`media`／`timeline`／`audio`／`copy`／`cost` |
| `message` | 指名道姓到镜号或节点 ID，不写「有些镜头」 |
| `evidence` | **放判据输入**（空数组、实际帧数、命中原文、抽样窗口），让第三方能复算；不放结论 |
| `suggestedAction` | 可执行的下一步，不写「请检查」 |
| `requiresVisualReview` | true ⇒ 必须人眼复核并由人在回执里签字；机器不得代为 PASS |

**三条硬规矩**

1. 禁止只报「发现 66 条问题」——**必须逐条给 code / 语境 / 判定 / 来源**。
2. `evidence` 里照录原文或原始数值；复算不出结论的报告不算报告。
3. `requiresVisualReview: true` 的条目未签字 ⇒ 本卡不得标 PASS。

## 三、severity 分级：追溯链断裂一律 error

| 缺陷类型 | 级别 | 说明 |
|---|---|---|
| 镜头无媒体绑定（`mediaNodeIds` 为空） | **error** | 逐镜验收与取证链断开 |
| 提示词过期（`fresh → stale` 未重算） | **error** | 旧提示词对应的产物，不能代表新脚本 |
| 孤儿素材（既未声明候选、又未绑定镜头／时间线） | **error** | 黑户素材点名处置：入账绑定或标废弃原因 |
| 成片节点无可用输出文件／URL | **error** | 「剪辑完成」不等于「可导出」 |
| 待人工复核未清 | **error** | 不得当 PASS 放行 |
| 缺陷报告输入指纹与当前项目不符 | **error** | 结论已过期，须重跑 |
| 音轨未登记 `a_` ID、混音后未逐镜核声画起点 | **error** | 音轨错位但「听起来对」，只靠听查不出 |
| 非对外文案的技术注释命中词表 | warning | 记录即可，不阻断 |
| 候选素材未标 `candidate` | warning | 提醒声明身份，不是产物缺陷 |

> **0 errors ≠ 可交付**：只要上表任一 error 存在，即便其余计数全绿、生成任务全部成功，
> 也不得进入 Phase 4。实证参照：某商业画布项目 52 件媒体、86 秒时间线、13 段 clip 齐备，
> 却因 13 镜全无绑定、成片无输出而停在终交付段，平台仍报 `errors: 0`。

## 四、三向绑定与关系证据

| 关系 | 必须有 | 证据字段写法 |
|---|---|---|
| 镜头 → 媒体 | `shotId.mediaNodeIds[]` | 列出每个媒体节点 ID |
| 媒体 → 镜头／时间线 | `media.shotIds[]` / `media.timelineNodeIds[]` | 两侧都要写，**单向关系不算绑定** |
| 时间线片段 → 源节点 | `clip.sourceNodeId` ＋ `clip.shotId` | 关系项附 `evidence`，注明「这条关系从哪个字段推出」 |

```json
{
  "type": "timeline-source",
  "sourceId": "tl_ep01",
  "targetId": "v_s04",
  "clipId": "clip_04",
  "evidence": "clipTimelineData.clips[].sourceNodeId"
}
```

**命名不算绑定**：节点名或文件名里带 `s04`、`EP01_s04` 只是文字，
`shotIds` 为空就仍是孤儿。绑定必须落在结构字段上——与本包「指纹以 md5 为准、轮次名不作指纹」同源。

**资产三态**：`candidate`（候选，允许未绑定但须声明）／`approved`（已过目）／`bound`（已进镜头或时间线）。
样片、备用首帧、链路验证片属于 `candidate`，不按缺陷处理。

## 五、报告指纹与结论过期

每次跑完本卡，报告头部必须带：

| 字段 | 含义 |
|---|---|
| `rulesVersion` | 判据版本，**冻结后不得临时放宽** |
| `dictVersion` | 词表／判据字典版本（与共享扫描器同源） |
| `inputHash` ＋ `inputBytes` | 本次输入快照的内容指纹与字节数 |
| `scannedAt` | 扫描时间 |
| `issues[]` | 按第二节 schema 逐条列出 |
| `summary` | pass / fail / total / passAll |

**过期判据**：当前项目内容指纹 ≠ 报告 `inputHash` ⇒ 报告自动标「**结论过期（待重跑）**」，
汇总数字从时间线／交付说明撤下，**重跑才恢复**。旧报告留档不删，但不得当作有效结论引用。

**人工不可覆盖**：主理人、成员、客户都不能把 FAIL 改成 PASS；
要改只能改输入（补绑定、重算提示词、补产物），再重跑。
这条与「主理人自己不能当裁判 ⇒ 强制独立盲评」互为双保险。

## 六、读取纪律：revision 钉版

多次／分页读取同一项目的 manifest、分镜、缺陷、时间线时，
**必须复用同一个 `expectedRevision`（或等价的内容指纹）**；
任一次返回的 revision 与基准不一致 ⇒ 停止拼接、重新取全量快照。

> 理由：把两个版本的分页结果拼成一份报告，会得出「看起来自洽、其实不存在」的结论。

---

## 七、投影 ≠ 持久化；字段 ≠ 有内容

- **有可打开的 URL 不等于文件已保存**。记录里 `bindingStatus: present` 仍可能
  `persistedResourceIdCount: 0`。交付件一律绑**内容 md5＋字节数**，并检查文件确实存在。
- **结构化字段不等于字段有值**。分镜表里预留了 `cinematics`（机位／运镜／焦段）却全为空对象，
  不能据此宣称「有镜头语言」。空字段要显式登记为「未填」，不能留白当作已填。
  能力边界见 `KNOWN_LIMITS.md` 第 4、9 条。

---

## 八、音频 evidence 契约

音频验收输出以下结构化指标（逐窗／逐镜），不只写「听起来对」：

`rmsDbfs`、`peakDbfs`、`clippedSampleRatio`、`silenceRanges`、`waveform`

- 环境声底「听得见」判据沿用既有 RMS ≥ −50 dBFS，并报静音占比；
- 「该静音」的窗口必须在 `silenceRanges` 里能被指出来；
- 混音后逐镜核声画起点（off-by-one 时音轨整体错位但每处都有声音）。

## 九、验证与被验证：两条工程纪律（v1.13.0）

> 来源：2026-11-13 画布工作台 P1 收口的两处真实故障（详见
> `docs/benchmark_canvas_gates_20261113.md` 第七节）。两条都不是「判据说错了」，
> 而是**判据的输入或解析出了问题**，却报出了像模像样的 FAIL 与条数。

### 9.1 验证动作本身会污染被测对象

- **现象**：回归脚本每轮给同一个图像节点 `+3s`，多轮复跑把时长累积到 23s，
  粗剪闸据此真报 `✗[C2] 单镜 ≤10s「关键帧静图」(n_demo3) 23s 超限`，
  状态栏掉到 `四道闸：3/4 PASS`——**判据没坏、闸没坏，是被测对象被前几轮测试改坏了**。
- **修法**：不改判据、不把 FAIL 改 PASS，而是在全部断言之后执行「测试项目复位」，
  把输入清回基线再重跑；复跑 58/58、闸恢复 `4/4 PASS`，输入指纹随之更新。
- **纪律**：
  1. 自检／回归脚本对被测对象**幂等**，跑完显式复位，并留复位实况（复位后的实测值与结论）；
  2. 出现 FAIL 时先用**只读探针**分辨「功能回归」与「夹具漂移」；探针不写状态，只读结论与 `inputHash`；
  3. 修法一律是**改输入再重跑**，与第五节「人工不可覆盖」是同一条纪律。
- **一句话**：**判据没错、输入被测试自己改坏，照样是假结论。**

### 9.2 硬闸与被检查对象之间要有可解析契约

- **现象**：命令名用字符串拼接生成时，检查器的正则只截到半截 `浮动 / 停靠「`，
  注册表 22 条被算成 18 条，硬闸 FAIL 并报「条数不符」——**内容没缺，是检查器读不懂写法**。
- **修法**：源码改为可解析的占位模板（`'浮动 / 停靠「{panel}」'`），
  检查器从定义处现读名称再展开，复跑 52 条 PASS。
- **纪律**：
  1. 凡「检查器从源码现读某项清单」，须登记一份书写契约（字段名／模板／占位符），检查器与被检查件同轮随动；
  2. 条数／枚举类断言与实值不符时，**先判「解析失败」再判「内容缺失」**，并把被截断的原文照录进 evidence；
  3. 禁止用拼接方式生成受检文本。
- **一句话**：**同源只保证内容一致，不保证读得懂；读不懂时报出的 FAIL 是假阳性。**

> 与第五节的关系：第五节管「结论过期」，本节管「输入被污染」与「判据读不懂输入」——
> 三种情况指向同一条底线：**报告所依据的那份输入，必须真能代表当时的项目。**

### 9.3 验证不采信被测对象自报

- **现象**：在线轮调某账本桥接工具恒返回 `entries:0`，据此得出「账本空、无缺陷」的结论。
- **独立真值**：另直连服务端点取回非空 `entries:[...]`，两轮均为 54 条、credits 1056，
  与端点读数一致，证明空结论出自取值层而非数据本身。
- **根因**：桥读 `l.data.ledger`，端点实际给的是 `entries`——字段名错读，不是数据不存在。
- **纪律**：
  1. 凡经被测对象提供的桥／代理／包装层取结论，须**另走独立通道取真值比对**，
     比对项含条数与关键字段值，不能只比「有没有返回」；
  2. 字段名映射写成可解析契约（与 9.2 同源），读不到时按「解析失败」处置，
     不得回落成「空数据」；
  3. 负向结论（「没有缺陷」「没有调用」）按铁律 C 附状态来源＋检索标识＋原文照录，
     不采信单方自报。
- **一句话**：**判据没错、取值层读错字段，照样报出像模像样的 0。**

## 十、回归资产与跨版本复算（v1.14.0）

> 来源：2026-11-17 对画布工作台五代技能包与常驻回归清单的只读考察（完整实据见
> `docs/benchmark_regression_discipline_20261117.md`）。v1.12.0 管「结论有没有证据」，
> v1.13.0 管「输入有没有被污染、读没读懂」，本节管**「这一次对，换一轮还对不对」**。

### 10.1 判据跨版本复算零漂移

四步做法，缺一不可：

1. 输入用**路径写死一致**的同一批 JSON，避免各版本自带样例差异被误读成判据差异；
2. 执行体用各版本**包内的**检查器，不是拿当前版本去跑旧包；
3. 当前版本另跑一遍作**独立基准**，防历代在同一处都错而互相自证；
4. 剔除时间派生字段后按固定键序序列化比 md5。

**书写契约（可解析）**：剔除字段逐项登记原因（`scannedAt`／`exportedAt`／`packedAt`／
`fileDigests[].fnv1a` 等时间或打包派生项）；固定时钟只作**显式通道**，默认分支仍用真实时钟。
若某代不支持该通道，须区分两类行为并附 rc／stdout 前缀／stderr 原文：静默忽略（rc=0，
输出回落原有形状）与报错退出（rc=2，带值 flag 被当路径）。**不得写「还没做」或笼统「失败」。**

**交叉印证防自证**：两路基线（current/defective 与 current/failing）应互不相等；
若相等，先查输入是否串线，再谈结论。

### 10.2 真 FAIL 输入作回归资产

- 真 FAIL 的输入（例如删掉媒体节点、样片闸 FAIL 3/4）存为基线资产，带 `inputHash`；
- 每轮回归不只跑 clean 输入，**必须把 FAIL 输入再跑一遍，结论仍须是 FAIL**；
- 附加通道（`--lessons`／`--evidence*`／`--pack-manifest`／`--fixed-time`）**只增不改**：
  叠加后基线段与基线逐字节相等，FAIL 不被「补了材料」洗白；
- FAIL 资产只作回归输入，不改判据、不放宽阈值。修法永远是改输入再重跑（同 5.3、9.1）。

### 10.3 常驻回归清单驱动与跨轮漂移检查

- 每轮必跑项写进**机器可读清单**（steps／currentValues／frozenArtifacts／noReplay／
  requiredGroups），runner 从清单读 steps 动态构造命令，不靠人记；
- **新增闸没写进清单，清单自检就应判 FAIL**——把执行遗漏变成可检出的错误；
- 跨轮漂移：冻结上轮清单副本，逐字段 diff 本轮清单，自动列出哪些当前值变了、是否同轮随动；
- **双向核验**：引用件当前值逐条比对（该随动的必须随动），历史留痕 needle 逐条比对
  （不该随动的必须不随动）——这是铁律 B 的机器化形态；
- 负向区分力：旧值回退／删 step／label 不随动／删冻结件／未登记漂移五种坏副本都应判 False。

### 10.4 三输入覆盖矩阵

| 输入类 | 用途 | 判据 |
|---|---|---|
| clean | 正常路径 | 全部通道 PASS |
| defective | 有缺陷但不阻断（缺陷落在 lessons 一类） | 缺陷被如实报出，不误放行 |
| failing | 真 FAIL | FAIL 结论稳定，不被任何附加通道改写 |

三类输入 × 各通道聚合成单一可查索引。矩阵里没有覆盖的格子写
`NOT_COVERED_BY_THIS_CHANNEL_RUN`，并附 status／stateSource／verbatim 三件
（检索标识写「全文检索 inputHash=xxx，命中 0 条」）。
**「无覆盖」是已核查的覆盖事实，不是待办，也不判故障。**
