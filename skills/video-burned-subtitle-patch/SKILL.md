# 烧录字幕像素级修补

## 0 先把铁律说死

1. **⛔ 不要信用户给的时间点、也不要信用户给的字。** 用户是凭记忆说的。**永抽帧看实际画面**。
   实战对照：用户说"0:10 秒出现的字幕是：印度洋" → 实测是「**印隔洋**·生物旺季」（真错）；用户同一条消息说
   "0:19 秒出现的是：海巍防污树脂" → 实测**就是这六个字、逐字放大全部正确**，无需改。
   若不抽帧，前者会改错位置，后者会白改一遍。
2. **⛔ 不要沿用上一次的字体标定。** 同一部片子里不同镜头/不同风格的字幕**字重可能差一倍**。
   实测：同一宣传片「更长防污期」= NotoSansSC w800；「印隔洋·生物旺季」= w350。每次重新标定。
3. **⛔ 不要假设字幕是静态的。** 实测：一处逐帧**上浮 32px + 水平收束 60px**（必须逐帧量）；另一处**完全静态**
   （坐标 75 帧恒定）。先扫，再决定用静态坐标还是逐帧几何。
4. **判据＝「修补帧与期望图的差异」必须远小于「修补帧与原片的差异」，且在字幕带内比。**
   只看整帧 PSNR 会漏判（字幕面积占比极小，改没改 PSNR 都高）。

## 1 先侦察：抽帧看真容

```bash
# 跨平台：依赖路径统一由 tools/env_probe.py 探测，不要手抄别人机器上的路径
PY="$(python3 tools/env_probe.py --print python)"
FF="$(python3 tools/env_probe.py --print ffmpeg)"
```
- **用 Python + `imageio_ffmpeg.get_ffmpeg_exe()` 调 ffmpeg**：Git Bash 里给原生 exe 传中文路径会踩编码/路径转换坑，
  Python 的 subprocess 走 CreateProcessW 宽字符，中文路径安全。
- 抽帧：`-vf "select='eq(n\,340)+eq(n\,594)'" -vsync 0 -f rawvideo -pix_fmt rgb24 out.raw`，
  或 `-frames:v 1` 存 PNG。**按帧号定位**，不要用 `-ss`（放在 `-i` 前会跳到关键帧）。
- **读图必须自己看**（Read 工具能看图）。把疑似区域裁出来放大 3–6 倍再读，整帧缩略图看不清笔画。

## 2 定位：字幕在哪些帧、每个字在哪一列

**亮度代理**：`mn = frame.min(axis=2)`（深色背景上的白字，用三通道最小值就能把字幕和背景分开）。

**找帧区间**：逐帧统计区域内的亮像素数，看状态跃迁。
```
帧 287 印18 隔17 洋16 ...   ← 多槽同时上升 = 字幕起点（此前是 7 左右的背景噪声）
帧 361 印253 隔254 洋253    ← 最后有字幕的帧
帧 362 bg 从 3.0 跳到 43.0  ← 换镜，字幕消失
```
- ⚠️ **噪声底**：字幕出现前墨迹像素并非 0（本例 alpha 0.02–0.04）。**起点判据用"多个字槽同步上升"**，
  不要用单点绝对值。
- ⚠️⚠️ **区间两头都必须靠"逐帧读"定，抽帧目检会骗你**（2026-10-01 实踩）。
  用 `fps=1/0.6` 抽字幕带粗测出的区间，本例**两头各差 24 帧**：起点早 24 帧 → 在字幕尚未出现的空白期
  **凭空画出孤立字**（用户一眼看出「10 秒有个图字」）；终点少 24 帧 → **错字残留**（用户「15 秒又出现了」）。
  **正解**：对「待改字所在字位」（已知的 x/y 框）**逐帧统计白像素数**，直接比对**原片 vs 已改版**，
  读出「误加 / 已修 / 漏修」三类区间 —— 比看整条字幕带灵敏得多：
  实测同一帧**整带**白像素 ≥600（画面里的白色物体污染了统计）而**该字位** = 0，用整带就会误判边界。

**定逐字槽位**：列投影（`mask.sum(axis=0)`）找连续非空段。汉字笔画间会有空隙，段数可能多于字数——
按"几段合并成一个字"人工归位，再用**字距（pitch）**交叉验证。
本例结果：印 525–549 / 隔 553–579 / 洋 583–608 / · 624–627 / 生 642–668 / 物 671–697 / 旺 701–727 / 季 729–756，pitch≈29。

## 3 alpha 曲线：淡入淡出与峰值

用**模型无关**的局部背景：`band_bg` = 字幕带**上方、下方各 10 行**的中位数均值（本例背景是深色海面，band_bg≈1.5–3.5）。

```
alpha ≈ (槽内墨迹 P99 - band_bg) / (255 - band_bg)
```
本例：帧 287 α=0.06 → 帧 344–361 α≈0.99。**峰值不是 1.0**，别默认满不透明。

- ⚠️ 参照字要选**笔画密度中等**的保留字（本例用「印」「洋」）。笔画太少的字（如「生」）P99 会偏低。

## 4 字体标定（**每次都要重做**）

**先量原字的两个数**：
- 墨迹高（`y` 方向非空行数）—— 决定字号
- **笔画游程中位宽**：逐行统计连续墨迹段长度取中位数 —— 决定字重

```python
def stroke_w(mask):                      # 二值墨迹的游程中位宽
    runs = []
    for row in mask:
        c = 0
        for v in row:
            runs.append(c) if (not v and c) else None
            c = c + 1 if v else 0
    return float(np.median([r for r in runs if r]))
```
本例：墨迹高 27px、游程中位宽 2.0px。渲染候选后**逐一比这两个数**选字重：
w300/w350 都是 2.0，w400 起变 3.0 → 取 **w350**（略粗一点，因为合片还要再编码一次、边缘会变细）。

**渲染参数**：
```python
f = ImageFont.truetype(r"C:\Windows\Fonts\NotoSansSC-VF.ttf", size)
f.set_variation_by_axes([weight])        # 可变字体必须显式设字重
d.text((cv//2, cv//2), ch, fill=255, font=f, anchor="mm")   # anchor="mm" 便于居中
# 裁到墨迹 bbox，再 cv2.resize 到目标墨迹高
```
- ⚠️ **加一次轻微高斯模糊 σ≈0.6**：片源字是压过的（边缘发灰），渲染字是硬的，不模糊会显得比周围"太锐"。
- ⚠️ 别用「整行 IoU」做标定 —— 字距不均匀时会失真（实测最高 IoU 只有 0.28，毫无判别力）。用上面的**两个标量**。

## 5 擦除 + 补背景

```python
win = frame[EY0:EY1, EX0:EX1]
m = (mn[EY0:EY1, EX0:EX1] - band_bg) > 12                 # 低阈值！淡入期字很淡
m = cv2.morphologyEx(m.astype(np.uint8), cv2.MORPH_OPEN, np.ones((2,2),np.uint8))
m = cv2.dilate(m, np.ones((3,3),np.uint8)) > 0            # 补回抗锯齿轮廓
for c in range(3):
    filled = cv2.inpaint(frame[:,:,c].astype(np.uint8), m.astype(np.uint8), 3, cv2.INPAINT_TELEA)
    base[:,:,c] = np.where(m, filled, win[:,:,c])
```
- ⚠️ **擦除窗右/左界必须避开相邻字的起点**。本例「洋」从 583 起，所以窗取 `x 551..583`（numpy 半开），
  再往右 1px 就会啃到「洋」。
- ⚠️ `cv2.inpaint(TELEA)` **只在"单字槽"这种小面积上可用**。若一次要抹掉整行大字（几百 px 宽），
  TELEA 靠边界传播会留斑块纹理 —— 那时改用自研 `bg_fill`（归一化卷积大核 + 由外向内逐层推进）。
- ⚠️ **光晕陷阱**：白字**实心覆盖处**（`α·A ≥ 0.95`）虽然不必改像素，但**求背景时仍须当作未知**；
  否则其中残留的原片亮墨迹成了"已知亮源"，会把周围背景拉出一圈光晕。
  正确写法：`bg = bg_fill(win, 完整掩码)` 求背景，再 `np.where(需要改的位置, bg, 原像素)` 应用。

## 6 合成 + 闭环标定不透明度

```
p_out = bg + α · A · (255 − bg)          # A = 字形覆盖度 0..1，α = 整体不透明度
```
**闭环标定**：目标 α 取**同一帧里保留下来的字**的实测 α，迭代 `α ← α · α_target / α_measured`，
使人眼真正看到的对照（绘制区 vs 保留区）一致。收敛阈 0.002，一般 3–8 次。

**逐帧断言（必做）**：
```python
full = fr.copy(); full[EY0:EY1, EX0:EX1] = out
assert np.abs(full - fr)[outside].max() == 0      # 擦除窗外的像素一个都不能动
```

## 7 合片（裸流整帧替换，音频不重编）

```
ffmpeg -i SRC -map 0:v -f rawvideo -pix_fmt rgb24 -      # 解码
  → Python 按【帧序号】把整帧替换成修补 PNG
  → ffmpeg -f rawvideo -pix_fmt rgb24 -s WxH -r FPS -i - \
      -c:v libx264 -preset slow -crf 16 -pix_fmt yuv420p -profile:v high \
      -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv video_only.mp4
  → ffmpeg -i video_only.mp4 -i SRC -map 0:v -map 1:a -c:v copy -c:a copy -movflags +faststart FINAL.mp4
```
- ⚠️⚠️ **`-c:v copy` 与 `-filter_complex` 写在同一条命令里 = 静默重编码**（2026-10-01 实踩）。
  症状：视频码率腰斩（2969→1607 kb/s）、时间基从 15360 变 90k、抽帧比对**平均像素差 64.5**（几乎全帧都不同），
  而 `-v error` 把警告吞了、**退出码仍是 0** —— 典型"看起来对、其实没生效"。
  **必须拆两步**：① 先只出音轨（`-filter_complex … -map "[aout]" -c:a pcm_s16le out.wav`）；
  ② 再纯净 remux（`-i SRC -i out.wav -map 0:v -map 1:a -c:v copy`）→ 逐像素差归 0。
  **自检判据**：remux 后与源逐帧比 `maxdiff == 0`，并核对码率 / tbn / `yuv420p(tv, bt709/…, progressive)` 与源一致。
- ⚠️ **帧号映射必须实测核对**，不要假设。抽同一帧比对 `maxdiff == 0` 才认。
  本例映射：某批修补图 `a1_XXXX` = 全局 `599+XXXX`；`b2_XXXX` = 全局 `929+XXXX`；`b3_XXXX` = **全局帧号本身**。
- ⚠️ **`ffprobe` 报的 fps 别信**。本例 tbn=15360、帧时长 512 → fps 恰 30；ffprobe 报 30.01 是 avg_frame_rate 取整。
- 合流时报 `Unknown cover type: 0x1` 是**无害告警**，不影响。
- 断言：`done == TOTAL` 且 `n_patched == len(PATCH)`，否则非 0 退出。

## 8 核验（合片后再独立验一遍）

**必须用"差异区三方比对"，不能只看整帧 PSNR**：
```python
# 1) 期望PNG 与 源帧 的差异区 bbox（自动定位，别手填）
d = np.abs(png - src).max(axis=2); ys, xs = np.where(d > 16)
# 2) 在该区内比较
MAD(out, PNG) << MAD(out, SRC)      # 实测 1.7~3.3  vs  16.4~56.4（比值 0.04~0.18）
```
- 判据：`MAD(out,PNG) < 0.35 × MAD(out,SRC)` ⇒ 修补确已落片。
- 另抽**非修补帧**比 `out↔src` 整帧 PSNR（实测 43.5–44.7 dB）确认只重编、没改内容。
- **音频**：解码成 `s16le/44.1k/stereo` 取 md5，与源比，应**完全相同**（用了 `-c:a copy`）。

## 9 目检（最后一关，不可省）

把「原片 / 修补」在字幕带内并排放大 3–6 倍，覆盖**淡入最淡的帧、峰值帧、结束帧**。看四件事：
**位置、字宽、笔画粗细、亮度**是否与左右保留字协调；背景有无涂抹/光晕；错字有无残影。
- 淡入最淡那帧最容易被忽视 —— 此时 alpha 只有 0.06，残影"看不见"但会在邻近帧露馅。

## 11 音频侧：用户同时要求改「配音读错的字」时

字幕错字常连带配音也读错（本例「向海渡强」配音确实读 dù）。**先判定原旁白能不能复现，再谈换法** ——

1. **测原旁白基频**：`F0 ≈ 72–89 Hz` ⟺ 低沉男声。**别用时域自相关**（会锁到谐波，同一文件能测出
   113 / 166 / 210 三个值）；用 **HPS 谐波积谱**：`hps = Sp * Sp[::2] * Sp[::3] * Sp[::4]`，限 60–300 Hz 取中位。
2. **拿本机 TTS 音色比**：edge-tts 7.2.8 的 4 个 zh-CN 男声**最低 125 Hz**（Yunjian），
   与原片差 5–6 个半音 → **音色不可复现**。此时**别硬做**，把选项摊给用户：
   ① 用 TTS 版（音色与前后句不一致）② 整条旁白重配（内部统一但整体音色变了）
   ③ 保持原配音只改字幕（音画不一致）④ **用户若知道原生成工具/账号 → 用原音色重生成该句（最优，无缝）**。
3. **edge-tts 对中文不返回 WordBoundary**（`stream()` 里没有词边界事件）→ 逐词时间轴拿不到；
   定位单音节只能走 **DTW 能量包络对齐**（精度 ±0.15s，对 0.25s 的音节是 60% 误差，慎用）。
4. **降调别写 `asetrate=sr*0.712`（那是升调）**：降调用 `asetrate=sr/0.712`，
   或用 edge-tts 原生 `pitch="-32Hz"`（更自然，不动共振峰比例）。
5. **替换整句会把那段配乐一起丢掉**（原片是旁白叠在连续配乐上，本机无 demucs 无法分离）
   → **必须在交付说明里讲清代价**，别让用户以为"只换了几帧画面"。
6. **拼接边界加 20ms `afade`**（本例边界正好落在语音间隙，不加也听不出，但别赌）。
