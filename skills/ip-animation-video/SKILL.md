### 1. 硬约束（必须先说，不要等做完才说）

**静态姿态位图（无分层）做不出真实操作动作。**

## 二、配音：先把 rate 标定准，别凭感觉调

### ★★ 坑 1（头号）：edge-tts 的时长≈完全反比于 rate，**精简文案完全无效**

实测拟合（样本段 28 字）：

```
T(r) = 6.94/(1+r) + 0.04          # r = rate 小数（+33% → r=0.33）
                                   # 6.94 = 音节时长；0.04 = 标点停顿（几乎为 0！）
```

**标点停顿只占 0.04s** —— 也就是说停顿也随 rate 一起缩放，不构成固定开销。

后果：**想压总时长只能提 rate。精简文案对总时长几乎没有影响。**

> 我在这里白跑过一轮：第一版 141 字 @+25% 得 29.67s 旁白；
> 我"精简到 130 字 + 回调到 +22%"，实测反而 30.07s。
> 字数少了 8%，时长却长了 1.3% —— 因为停顿和音节一起被 rate 缩放，字数不是主导项。

**正解**：先用 4 个 rate 点（0/25/50/75%）标定曲线，再解出目标 rate：

```python
# test_rate.py 核心
pts = []
for r in (0, 25, 50, 75):
    d = await tts_one(SAMPLE, r)            # 用最长的一段当样本
    pts.append((1.0/(1.0+r/100.0), d))      # x = 1/(1+r)
# 线性拟合 T = A*x + B  →  A=音节, B=停顿
A = ...; B = ...
# 再按字符数等比缩放预测全片，扫 rate 求最接近目标总长的那个
```

### ★★★ 坑 1b：**标定只是"缩小搜索范围"，实测迭代才是准的**

上面的标定用「样本段字符数 → 全片字符数」**等比缩放**预测总时长，
但**段间的语气与停顿差异很大**（有的段是短句连读、有的是带逗号的叙述），
等比缩放的误差可以到 **±4~5 秒**。

**实测（本项目，云健男声，6 段 132 字）**：

| 预测 | 实测 | 偏差 |
|---|---|---|
| `test_rate.py` 预测 +30% → 29.81s | 实测 **34.44s** | **+4.63s** |

**正解 = 拿真实文案跑 3 轮实测**，每轮只调 rate：

```
+30% → 34.44s
+42% → 32.40s     (每 +12% 约降 2s)
+55% → 30.56s
→ 再收紧最长段(m4)的目标时长 7.6s → 6.2s，最终 29.16s ✓
```

**两条纪律**：
1. **别信预测值**，一定要用**真实的分段文案**跑出来量总长
2. 如果 rate 已经推到 +55% 还超时长，**别再提 rate**（会失真难听），
   改为**收紧最长的那个段落的目标时长**（即精简该段台词，或把该段拆给相邻段）

### ★ 云健（zh-CN-YunjianNeural）实测 rate 曲线

```
T(r) = 5.60/(1+r) + 0.06      # 样本「第一步清理，第二步打磨，第三步刷底漆，第四步刷面漆。」(28字)
  +0%→5.66s / +25%→4.54s / +50%→3.79s / +75%→3.26s
```

> 与坑 1 的云希（YunxiNeural，`T=6.94/(1+r)+0.04`）对比：
> **云健的基频更短（5.60 < 6.94）**，即同样 rate 下云健更快。
> 换音色必须**重新标定**，不能套用别的音色的公式。

### ★ 坑 2：多音字 —— 单字列读会读错

「清、磨、底、面」这种**单字列举**交给 TTS，「磨」有 mó（打磨）/ mò（磨面）两读，会读错。

**正解**：**旁白读完整词，画面用单字块**，两者互不依赖：
- 旁白文本：`记住四步：清理、打磨、底漆、面漆。`
- 画面：四个单字块「清 磨 底 面」做进度指示

### ★ 坑 3：edge-tts 会限流（`NoAudioReceived`），必须退避重试

```python
async def tts_one(text, mp3, tries=5):
    for k in range(tries):
        try:
            await edge_tts.Communicate(text, VOICE, rate=RATE).save(mp3)
            if os.path.getsize(mp3) > 2000:      # ★ 还要验大小，防半截文件
```

### ★★★ 坑 3b：字幕**必须用配音原文**，并用 WordBoundary 词级时间戳对齐

**症状**：客户说"**语音与字幕不齐**"。
**根因**：字幕写成了配音的"提炼短句"（更短、更好排版），于是**配音比字幕多念半句** ——
观众"听到的看不到"。

| 段 | 字幕（看到的） | 配音（听到的） |
|---|---|---|
| m1 | 我是小卫，某防水品牌A小卫士！ | …小卫士。**今天教你一招，屋顶漏水自己搞定。** |
| m3 | 某防水品牌A七件套，渗进去才扛得住！ | **别急，某防水品牌A七件套来了。**底漆渗进水泥缝… |
| m5 | 防水做到位，经得起日晒雨淋 | **你看，水泼上去自己滚下来。**… |

**正解两条**（缺一不可）：
1. **字幕 = 配音原文**。想精简就精简**配音文本**，不要只精简字幕。
2. **按句切换，用 TTS 的词级时间戳定位** —— 不要按字符数估算。

```python
async def tts_with_bounds(text, voice, rate, mp3):
    """生成音频 + 收集 WordBoundary 词级时间戳（单位 100ns，秒 = offset/1e7）。"""
    bounds = []
    comm = edge_tts.Communicate(text, voice, rate=rate)
    with open(mp3, "wb") as fh:
        async for ch in comm.stream():
            if ch["type"] == "audio":
                fh.write(ch["data"])
            elif ch["type"] == "WordBoundary":
                bounds.append((ch["offset"], ch["duration"], ch["text"]))
    return bounds

def build_cues(text, bounds, vo_dur):
    """按 。！？ 切句；用"累积字符数"把句界对齐到 WordBoundary 序列。"""
    parts = [p.strip() for p in re.split(r"(?<=[。！？])", text) if p.strip()]
    if len(parts) <= 1:
        return [{"text": text.strip(), "t0": 0.0, "t1": round(vo_dur, 3)}]
    clean = lambda s: re.sub(r"[^\w\u4e00-\u9fff]", "", s)
    cum, n = [], 0
    for p in parts:
        n += len(clean(p)); cum.append(n)
    cues, acc, wi, t_prev = [], 0, 0, 0.0
    for k, target in enumerate(cum):
        while wi < len(bounds) and acc < target:
            acc += len(clean(bounds[wi][2])) or 1; wi += 1
        off, dur, _ = bounds[wi-1] if wi else (0, 0, "")
        t_end = min(round((off+dur)/1e7, 3), vo_dur) if wi else vo_dur*target/cum[-1]
        cues.append({"text": parts[k], "t0": round(t_prev, 3),
                     "t1": max(t_end, round(t_prev+0.30, 3))})
        t_prev = cues[-1]["t1"]
    cues[-1]["t1"] = round(vo_dur, 3)
    return cues          # 写进 timeline.json 的 seg["cues"]
```

**★ 配套：长句按显示宽度自动拆行**。改用配音原文后句子会变长
（本项目 m4「第一步清理，…，第四步刷面漆。」**27 字**）→ 必超字幕安全区。
按逗号右切、尽量均分，再**按字符数比例把该 cue 时长分给各子片段**：

```python
def split_wide(text, max_w=860):
    if _tw(text) <= max_w: return [text]
    # ★ 分隔符必须包含【冒号】：否则「有一点要提前说清楚：底漆固化前有气味，」
    #   会被当成一整段（19 字 ≈ 936px）原样吐出 → 仍超宽
    segs = [s for s in re.findall(r"[^，,、；;：:]*[，,、；;：:]?", text) if s]
    out, cur = [], ""
    for s in segs:
        if cur and _tw(cur+s) > max_w:
            out.append(cur.rstrip("，,、；;")); cur = s
        else:
            cur += s
    if cur: out.append(cur.rstrip("，,、；;"))
    # 兜底：单段无标点可分时按字符硬切，保证绝不超宽
    final = []
    for p in out or [text]:
        while _tw(p) > max_w and len(p) > 1:
            k = len(p)
            while k > 1 and _tw(p[:k]) > max_w: k -= 1
            final.append(p[:k]); p = p[k:]
        if p: final.append(p)
    return final or [text]
```
意外收益：本项目这句被拆成「第一步清理，第二步打磨」+「第三步刷底漆，第四步刷面漆」，
**正好对应画面 2×2 卡片网格的上行/下行**。

**断言必须跟着改**（否则检查的还是旧字段、等于没验）：
逐条 cue 查 ①宽度不超安全区 ②`t1 > t0` ③首条 `t0≈0` ④**相邻 cue 无断档**（`a.t1 ≈ b.t0`）。

**成片核验再加一层像素证据**（不只验数据）：**逐 cue 中点抽帧查字幕区白像素**，
并比较**相邻 cue 的字幕区图像差异**（缩到 54×6 灰度签名算平均绝对差 > 6）
—— 证明"按时间轴切换"**真的生效**，而不是只写了数据没渲染出来。

**★ 改了字幕就要全量重渲**：字幕在 `render_frame` 末尾，影响**每一帧**，
不能像改单个镜头那样只补渲一段。

### ★★★ 坑 5k：抠图的三个「静默失败」（本轮新增，三个都真踩过）

**① `cv2.imwrite` 在中文路径下静默失败**
脚本里明明定义了 `imwrite_u()`（`imencode` + `tofile`），却顺手写了 `cv2.imwrite`
→ **9 个输出文件全部没落盘，且零报错**（我第二次踩这个）。
**判据：输出目录为空 = 写失败。**不要以"没报错"当作"写成功了"。

**② 「边缘不连通」→ 整张图变成前景**
现象：某个样本抠出来是**全不透明且不裁边**（输出尺寸 = 原图尺寸）。
诊断：`dist < THR` 占比 81%（完全正常），故障出在**最大背景连通块没有触及画面边缘**
—— 最外一圈像素恰好被判成"非背景"，于是 `border` 集合近乎为空 →
`outside` 全 False → `alpha` 全 255。
修法（一行）：
```python
cand[0, :] = cand[-1, :] = cand[:, 0] = cand[:, -1] = 1   # 最外一圈强制当背景种子
```
**判据：只要出现「某个样本整图不透明」，先查这一步，别急着调阈值。**

**③ Canny 边缘墙要看素材，不是万能的**

| 素材类型 | 需不需要边缘墙 |
|---|---|
| 纯白产品在纯白背景上（几乎同色） | **需要** —— 否则产品被抠穿成镂空 |
| 角色彩色、背景浅灰（本批） | **不需要**，用了反而有害：把最外圈判成非背景 → 触发 ② |

判据：**看背景干净程度**。背景 `dist` 中位数 < 5（本批 1.7）就可以不用边缘墙，
改用一个严阈值（16 左右）即可；这样还能保住**白手套/白鞋**这类"距背景约 26"的浅色部件——
用宽阈值（30）会把它们当背景抠掉。

### ★★ 结论：表情包 / 贴纸类素材，配文抠不掉就**别抠**

这类素材的配文（如「边角我来看。」「搞定！」）常与角色**物理重叠或紧贴**，
三条路都被实测堵死：

| 方法 | 结果 |
|---|---|
| 面积过滤（只留最大连通块） | 文字与主体连成一块，**无效** |
| 形态学开运算（腐蚀 7px 断细连接） | 不是细连接而是重叠，**断不开** |
| 颜色掩码定位（配文是单色） | 配文色与角色配色接近（实测文字 RGB(3,79,158) vs 裤子蓝），**掩码混进主体** |

**正解：换素材。** 同一 IP 通常已有**干净的单独姿态图**（本项目用海报同款的 4 个姿态，
风格完全一致，直接可用）；表情包这类素材**就让它当表情包**——那才是它的正确用法。
判断成本花在"抠一版试试"之前，比抠到一半再放弃便宜得多。

## 三、渲染引擎架构

### 核心：一个 `Cfg` 承载全部版式常量，绘制函数只读它

```python
class Cfg:
    """两种画幅的全部版式常量。绘制函数不写死任何坐标。"""
    def __init__(self, orient):
        if orient == "v":
            self.W, self.H = 1080, 1920
            self.HERO_H, self.HERO_CX, self.STAGE_BY = 640, 330, 1244
            self.DIA_BOX = (622, 856, 1030, 1244)
            self.T_HEAD_CX = 540          # 片头/片尾角色居中
            self.HERO_BY_HERO = 1568      # 片头角色基线（更靠下 = 主角登场感）
        else:
            self.W, self.H = 1920, 1080
            # ★ 横版是「左右分栏」，不是把竖版压扁
            self.HERO_H, self.HERO_CX, self.STAGE_BY = 650, 470, 960
            self.DIA_BOX = (1010, 372, 1830, 700)
            self.T_HEAD_CX = 1420         # 右栏中心
```

### ★★ 坑 6：双画幅**不能等比压扁**

把竖版坐标按比例缩到 1080 高，要点卡会**压到角色身上**（实测踩过）。
横版必须重新设计为**左右分栏**：左栏 = 角色 + 四字进度；右栏 = 标题 + 示意图 + 要点卡。

### ★★★ 坑 6b：横版右栏**必须自上而下顺序编排 + 加几何断言**（客户看片才发现）

左右分栏只解决了"压角色"，**没解决"右栏内部互压"**。实测一版横版出片后被客户一句话退回
（"横版的有问题"），目检+抽帧才定位到 **4 处硬伤**，全都是"各元素手工拍 y、彼此不知道对方存在"造成：

| 症状 | 根因 | 修法 |
|---|---|---|
| **副标题下半截被示意图卡片吃掉**，小字像重影 | 标题 `TITLE_Y=244`，副标画在 `+106`（字号 31→字高约 37，底边 ≈368）；示意图顶边却放 350 → **压 18px** | 副标位置改为**算出来**的 `SUB_CY`，示意图顶边 = 副标底边 + 28 |
| **片头右栏空半屏** | 小卫基线 960、高 650 → 头顶 310；标题却放在 y=620 → 中间 350~880 全空 | 片头**沿用步骤页骨架**（左小卫 / 右标题），不要另起一套 |
| **片头标题骑到顶部品牌条上** | 想"往上挪填空档"，但 1080 高的横版顶部是品牌条（底 ≈127） | 标题顶必须 ≥ 品牌条底 + 12 |
| **小卫脚被底部信息条切掉** | 为躲开四字进度把小卫基线调到 1000，信息条在 942 | 断言 `HERO_BY_HERO + 10 <= BAR_Y` |

**根本解法（不是再手调一遍 y）**：

1. **自上而下反推**。右栏高度是硬的，按
   `标题块 → 示意图 → 要点卡 → 信息条` 顺序编排，**每个元素的 top 由上一个的 bottom 算出**：
   ```python
   self.BAR_Y = self.H - 54 - self.BAR_H                 # 先钉最底的
   bul_bot = BULLET_Y + 3*BULLET_H + 2*BULLET_GAP        # 按 3 条定容
   assert bul_bot + 14 <= self.BAR_Y                     # 断言，不是注释
   sub_bot = SUB_CY + int(SUB_FS*0.62)
   dia_top = sub_bot + 28                                # 示意顶上沿跟着副标走
   dia_bot = BULLET_Y - 18
   ```
2. **加 `render.py check` 模式**，用**真实字体度量**（`ImageFont.getbbox`/`getlength`）断言，
   而不是"字号×0.62"估算。至少覆盖：副标不压示意图、示意不压要点卡、末条要点卡不压信息条、
   信息条不出画、编号不叠标题、最长副标/最长要点卡不溢出栏宽、片头标题不骑品牌条、角色不出画。
   任一失败 `sys.exit(1)`。**每改完 Cfg 必跑**。
3. **成片像素层再验一遍**（坐标对了也可能被别的图层盖住，例如示意卡片的入场缩放）：
   在"副标下沿 ~ 示意顶边"的窄带里统计近白像素占比，>10% 即判卡片爬上来。

**副产物两个版式知识**：

- **示意图不能铺满宽栏**。横版右栏 860px 宽、纵向只 ~310px → 宽高比 2.8:1，读起来是"色带"
  （客户原话"看着像一条横带"）。卡宽改为 `高 × 1.85` 且**左对齐右栏左边**（与要点卡同起点，
  列是齐的、图也不扁）。更彻底的解法是把**整个右栏收窄**（860→660），左栏角色相应右移，
  否则窄卡右侧会空一大片。
- **示意图地面位置要随宽高比走**。竖版 1.05:1 时地面居中偏上（0.46）很自然；横版宽扁图若还按
  0.46，天空只剩一条、土层占近半。按 `up = 0.46 + 0.16*clamp((ar-1)/1)` 让比例越大天空越多。

### ★★ 坑 6c：断言必须覆盖"**角色压字幕 / 角色压品牌文字**"

初版断言只查了"字幕不超安全区、不出画"，结果目检发现 **4 处角色与文字/板块的真实冲突**：

| 冲突 | 症状 | 修法 |
|---|---|---|
| 片尾 小卫脚 → 压二维码块顶 | 角色腿盖住扫码文案 | 小卫基线上移 |
| 中段 小卫脚 → 压字幕顶 | 角色脚踩在字幕上 | 小卫缩小 + 基线上移 |
| 产品镜头 桶右缘 → 叠小卫左缘 | 产品桶与角色重叠 | 两者横向拉开 |
| 片尾 小卫顶 → 压品牌条底 | 角色头顶盖住品牌标语 | 小卫缩小 + 下移 |

**根因**：断言写成了"元素之间"（网格/卡片/字幕），漏了"**角色**"这个最大且位置最灵活的元素。

**正解**：断言里**角色必须参与每一次纵向/横向编排检查**。
且**角色尺寸要用实测比例算，不能估**：

```python
# 素材是"按高度等比缩放"，所以宽度 = 高度 × 素材宽高比
# 必须先实测素材的 w/h 比，别拿"高度"当"宽度"用
# bucket_cut 1110x1600 → w/h=0.694 ; abian_thumb 1214x1828 → w/h=0.664
M3_BUCKET_CX, M3_BUCKET_R = 330, int(760*1.02*0.694/2)  # = 269
M3_HERO_CX,   M3_HERO_HALF = 884, int(440*0.664/2)       # = 146
ck(M3_BUCKET_CX + M3_BUCKET_R + 40 <= M3_HERO_CX - M3_HERO_HALF, "...")
ck(M3_HERO_CX + M3_HERO_HALF <= W - 40, "小卫右缘出画")   # ★ 记得查右侧出画
```

> 我在这一处连错两轮：先把"桶高 760"当成"桶宽"，算出左缘 -58 出画；
> 修正后又忘了查"小卫右缘 1106 > 1080-40 出画"。**两侧出画都要查。**

### ★★ 流程纪律：客户说"X 有问题"但没说什么问题时

**先抽帧目检定位，不要凭猜测改代码；也不要只回一句"具体哪里有问题？"就把球踢回去。**
本次客户只说「横版的有问题」，正确做法是：

1. 抽该画幅**每个段落**的关键帧（含段首/段中/段末），逐张目检；
2. 用**检测线图**把候选版式的关键 y（卡片上下边、要点卡、信息条、标题块）叠到帧上，
   一眼就能看出谁压谁 —— 比"估计应该没重叠"可靠得多；
3. 把定位到的**具体症状 + 根因 + 修法**列成清单给客户，**同时用 AskUserQuestion 让他勾选确认**
   （可多选，也可选"整体重排一遍"）；
4. 得到确认后再动手。本次客户勾的是「整体都重排一遍」，说明单点修补不够 ——
   这类反馈往往不是一处，而是"版式没系统设计"，值得整体重排 + 加断言防腐。

### 性能：静态层预渲染，每帧 `copy`

```python
_LAY = {}
def base_bg(c):                 # 渐变背景 + 光斑 + 水珠，只生成一次
    if ("bg", c.orient) not in _LAY: ...
    return _LAY[("bg", c.orient)]

def brand_layer(c):             # 品牌条也是预渲染的一整层
    ...
def render_frame(c, t):
    im = base_bg(c).copy()      # ★ 每帧只 copy，不重建
    ...
```
实测：不预渲染时每帧要新建多个 1080×1920 RGBA 图层；预渲染后 **75–81 ms/帧**，
全量 960 帧约 2.9 分钟/画幅。

角色素材也要按目标高度预缩放缓存（原图 1500×1800，逐帧 resize 会拖垮速度）。

### ★★ 两个高频"隐形"性能杀手：全幅高斯模糊 & 不缓存

本项目初版只有 **0.4 帧/秒**（全量 875 帧要 40 分钟）。两个杀手：

| 杀手 | 症状 | 解 |
|---|---|---|
| **投影每帧新建全幅图 + 高斯模糊** | `Image.new("L",(1080,1920))` + `GaussianBlur(24)` 每帧至少一次（多元素镜头更多） | **只在小画布上模糊**（`pad = blur*3`）再贴回原位 + **按参数缓存**（`_SH[(cx,cy,rx,ry,alpha,blur)]`） |
| **脉动光晕每帧全幅 `blur(90)`** | 呼吸/光晕类效果 | 把脉动量**量化成有限档位**（如 `int(pulse*12)`）分档缓存（`_GLOW[key]`） |

```python
def shadow(im, cx, cy, rx, ry, alpha=80, blur=None):
    blur = blur or int(W*0.022)
    key = (int(cx),int(cy),int(rx),int(ry),int(alpha),blur)
    sh = _SH.get(key)
    if sh is None:
        pad = blur*3
        g = Image.new("L", (int(rx*2+pad*2), int(ry*2+pad*2)), 0)
        ImageDraw.Draw(g).ellipse((pad,pad,pad+rx*2,pad+ry*2), fill=alpha)
        g = g.filter(ImageFilter.GaussianBlur(blur))
        sh = Image.new("RGBA", g.size, (14,40,70,0)); sh.putalpha(g)
        _SH[key] = sh
    im.alpha_composite(sh, (int(cx-rx-blur*3), int(cy-ry-blur*3)))
```
实测 **0.4 → 1.11 帧/秒（2.8 倍）**，全量 875 帧从 40 分钟降到 13 分钟。

### ★★ 改一个小节时，别全量重渲 —— 按帧号区间补渲

客户改片尾/某一段时，没必要把 900 帧全渲一遍（若每帧 ~0.9s，全量 13 分钟、单段 1 分钟）。

```python
tl = json.load(open("timeline.json", encoding="utf-8"))
start = float(tl["segs"][5]["start"])      # 要改的那一段起点
f0 = int(round(start*30)); f1 = int(round(tl["total"]*30))
for i in range(f0, f1):                     # 只重写该区间的帧文件
    r.render_frame(i/30.0).save(f"frames/f{i:05d}.png")
```

**⚠️ 三个必查点**（否则会渲出半旧半新的帧）：
1. **叠化转场要不要往前多渲一段**：`TR_DUR` 内新镜的内容会混进**前一个区间**的末尾帧
   （本次 m6 起 26.11s、`TR_DUR=0.32` → 783~792 帧也含 m6 内容，故从 783 起渲）
2. **改动的全局影响**：若动了 `Cfg`／字幕位置／缓存键，那**所有段都要重渲**，不能只补一段
3. 补渲后**必须重跑 `render.py check` + 成片核验**，确认帧数与时长没变

## 四、"纸片人"动效（无分层素材的正确做法）

角色是静态位图，动效只能停在整体变换层面：

```python
def put_hero(im, c, pose, cx, by, h, rot=0.0, dy=0.0, alpha=1.0):
    hh = hero(pose, h)                                    # 预缩放缓存
    if abs(rot) > 0.01:
        hh = hh.rotate(rot, resample=Image.BICUBIC, expand=True,
                       fillcolor=(0,0,0,0))                   # RGBA 旋转要显式透明填充
    if alpha < 0.999: hh = _with_alpha(hh, alpha)
    im.alpha_composite(hh, (int(cx-hh.width/2), int(by-hh.height+dy)))
```

- **入场**：`eob` 缓动滑入（位移）
- **持续呼吸**：`dy = sin(t*2.35)*5`（±5px，周期约 2.7s）
- **微幅摆动**：`rot = sin(t*1.55)*1.5`（±1.5°）
- **落地阴影**：椭圆 `GaussianBlur` 软阴影，否则位图角色会"飘"在画面上

### ★ 坑 7：姿态不足以区分段落时，用**入场方向逐段交替**

角色往往只有 3~4 个姿态，若连续几步用同一姿态**又同向入场**，观众会以为"这段没换"。

```python
sgn = 1.0 if idx % 2 == 0 else -1.0        # 逐段交替左右
off = (1 - a2) * c.W * 0.30 * sgn
```

再加**进度字段首弹跳**（`sc = 1.16 + 0.20*max(0, 1-t/0.5)`），节奏感立刻出来。

## 五、示意图：要表"机理"，不是画"图标"

这是本类视频**最容易做砸**的地方。

### ★★ 坑 5（最值钱）：示意图要自问"它**读起来像什么**"，而不是"我画的是什么"

底漆那一张，初版用 **"整块蓝矩形从顶面往下渗"** 表达渗透。
但视觉上它读起来是 **"表面刷了一层厚的"** —— 与产品主张（渗入固结）**正好相反**。

**正解**：灰基层 + 画**明显的孔隙** + **蓝色只填进孔里**：

```python
_soil(d, ix0, ix1, gy, iy1)                      # 灰基层
for k in range(n):                               # 先画孔（深灰）
    d.line((xx, gy, xx, iy1), fill=(96,110,126), width=8)
for k in range(n):                               # 蓝色只填孔，且只填到渗透深度
    d.line((xx, gy, xx, min(gy+depth, iy1)), fill=(30,111,196), width=8)
d.rectangle((ix0, gy-20, ix1, gy), fill=(52,136,214))   # 顶面余料（薄薄一层）
```

### ★★ 坑 5b：示意图的「**动作方向**」会整体读反

画"施工动作"时，**工具**与「已处理区 / 待处理区」必须**分列在工具两侧**。

反例（实测）：把旧涂层画在左侧、铲刀放到右侧、中间空一片 ——
视觉上完全读不出"在清理"，像"铲刀在空地上待着"。

正解：**铲刀自左向右推进** —— 左侧 = 已铲干净的基层，右侧 = 待铲的废旧涂层，
再加断面毛刺强调"刚被铲过"。

> **自检话术**：问自己"这个动作的**已完成区**和**待处理区**分别在哪一侧？"
> 两者若不在工具两侧，画法就是反的。

### ★★ 坑 5c：**颜色必须核对实物，不能凭印象**

我按"防水涂料 = 蓝"的想当然，把**面漆**画成了蓝色。
实际是 —— **蓝色是底漆**，**面漆是灰色**。整段示意图的色义反了。

凡示意图里要表达实物颜色，**先确认实物色再动手**（看产品实拍/问用户），
不要用"行业印象"替代。

改灰之后，灰面层压在灰基层上需要靠三样东西区分：
**更亮 + 顶面高光 + 滚涂纹理**。

### ★★ 坑 5d：**单色填充 ≠ 渐变填充，语义完全不同**

同一个"填充孔隙"的动作：

| 画法 | 读起来是 |
|---|---|
| 单色填满孔隙 | "把孔**填满**了"（= 表面施工） |
| **上深下浅的渐变** | "**越往下渗得越浅**"（= 渗进去） |

表达"渗透"必须用**渐变**。再叠三样，渗透才真正立得住：
**渗透前沿亮线** + **向下指示箭头**（循环下落淡出）+ **顶面余料随渗透变薄**。

### ★ 坑 5e：一步里给「**两拍**」更好看

如"清理" = **铲除 → 吹扫浮尘**。单拍容易显单薄；
第二拍还能顺便覆盖首拍工具（铲刀）的淡出，画面不会出现"工具凭空消失"。
连"工具淡出"都要设计：`ka = clamp(1.0 - (t - 2.10) / 0.40)`。

### ★★ 坑 5f：文案一加长，画面就会「**空转**」

段落时长由旁白决定。改文案 → 段落变长，但画面元素时序没跟着变，
就会出现"所有元素都出完了，画面静止 10 秒"。

**三处必须同步拉伸**：

| 要素 | 做法 |
|---|---|
| **要点卡出现时刻** | 别固定 `t0 + i*0.18`。按「**该句累计字符数 ÷ 本段总字符数 × 旁白时长**」算出每条对齐旁白念到它的时点（画面比语音略早 0.3s） |
| **示意图动画时长** | `prog = clamp((t - 0.45) / 时长)` 里的时长要跟着拉长（本次渗透 1.9s → 4.2s，成膜 1.5s → 2.8s） |
| **布局容量** | 条数一变就要重算：`BULLET_Y + n*H + (n-1)*GAP` 是否小于底部条 y。本次要点卡 2→3 条时，横版原参数第 3 条会**压到底部信息条** |

```python
# 要点卡出现时刻对齐旁白
def draw_bullets(im, c, items, t, t0, gaps=None):
    for i, txt in enumerate(items):
        d0 = t0 + (gaps[i] if gaps and i < len(gaps) else i * 0.18)
        a = eoc((t - d0) / 0.45)
        ...
BULLET_GAPS = {"s3": [0.0, 3.9, 6.1], "s4": [0.0, 2.9]}
```

**画面分层承载原则**：旁白可以长，画面要提炼 ——
长句放旁白，画面用「短副标 + 多条要点卡」承载，不要让一行字幕塞满整句。

### ★★★ 坑 5g：客户说"用 AI 生成画面"时，**必须拆开问"哪些能用 AI"**

客户原话"风格 3D 卡通动画"很容易被理解成"整支片子都交给 AI 生成"。
**这是错的，且后果不可逆**：

| 画面元素 | 能不能 AI 生成 | 理由 |
|---|---|---|
| 无品牌文字的 3D 场景（蓝天白云/小房子/屋檐/光晕/水珠/展台） | ✅ 能 | 没有需要逐字准确的文字，AI 做得比程序化绘制更好看 |
| **固定 IP 形象**（本项目"小卫"） | ❌ **绝不能** | AI 必然**形象漂移**——同一角色在不同镜头会长得不一样，系列片就废了 |
| **产品包装/logo/型号文字** | ❌ **绝不能** | AI 会把「指铠 ZK-720」这类型号做成糊字/错字。**包装做错比画面丑严重得多** |

**正解 = 混用**：AI 只做"背景层"，IP 形象与产品用**真实素材**（透明 PNG）叠上去。

于是必须**二次追问**（第一次只问"要不要用 AI"，用户很可能答"要"）：

```json
{"question": "画面方案怎么定？（AI 生成的画面里，IP 形象和产品包装的文字必然做糊/漂移）",
 "options": [
   {"label": "混用：AI 做背景，小卫用素材（推荐）", "description": "背景更好看，IP 与产品 100% 准确"},
   {"label": "全 AI 生成", "description": "快，但角色形象会漂移、产品型号会做错"},
   {"label": "全程序化绘制", "description": "完全可控，但背景较朴素"}]}
```

**⚠️ AI 生成图的两个必做后处理**：
1. **切水印**：多数文生图工具会在右下角打「AI生成 WORKBUDDY」水印
   → `crop((0, 0, int(w*0.78), int(h*0.92)))` 切掉（比例按实测调）
2. **cover 缩放**：AI 图比例（常 1024×1536）与帧（1080×1920）不同
   → `sc = max(W/im.width, H/im.height)` 后居中裁，不要直接 resize（会变形）

**"贴纸感"的成因与解**：真实素材是照片质感，叠在 3D 卡通背景上容易像贴纸。
主因是**素材尺寸过大**（占画面过高比例）。
→ 把角色缩到 **440~620px**（竖版 1080 宽时约占 40~57% 高度），
并让它**站在场景的地面位置**，各元素分列不重叠。

### ★★★ 坑 5h：招商/宣传类文案，**动手前先做广告法合规体检**

分镜脚本是客户给的，但**违规风险是制作者和发布者的**。
拿到脚本第一件事不是渲染，是**逐句扫这四类高危表述**：

| 类型 | 典型表述（本项目实例） | 处理 |
|---|---|---|
| **效果保证性承诺** | 「十年不漏」「保证不漏」「永久」「终身」 | **删除**或改为不涉年限的定性描述 |
| **用量/性能数据** | 「一套能刷 5-8 平方」「渗进 3-5 毫米」 | **删除**（除有第三方检测报告支撑） |
| **实证式效果演示** | 「水泼上去自己滚下来」（画面演示比口头宣称举证责任更重） | 保留画面可以，台词改为**不承诺具体年限**的描述 |
| **个人手机号公开投放** | 招商电话留个人 13x 号 | 改为**企业微信 / 400 / 二维码位**（个人号易被骚扰爬取） |

**替代写法**：把"数值承诺"换成"机理性定性描述" ——
「渗进 3-5 毫米」→「**渗进水泥缝，跟基层咬在一起**」；
「十年不漏」→「**经得起日晒雨淋**」。

★ 这类改写**必须在渲染前完成**——已经渲染好的字幕/配音返工成本极高。
★ 交付时**附一张改写对照表**（原表述 → 风险类型 → 改后），让客户知道改了什么、为什么改。

### ★★★ 坑 5i：客户说"抠图"时，先判断**这批素材到底能不能抠**

客户说"把这几件产品抠图放到画面里"时，**不要直接动手抠**。先看素材的三个致命条件：

| 检查项 | 不能抠的信号 | 后果 |
|---|---|---|
| **背景** | 木地板/桌面/地毯等**有纹理的实景**（不是纯色幕布） | 边缘带木纹残影、毛边 |
| **手/人** | 手指压着产品、手掌托底 | 手没法自动去除，抠出来要么带手、要么缺一块 |
| **姿态** | 产品横躺/倒置 | 抠出来是歪的，摆进画面很别扭 |
| **与背景色温** | 产品与背景同色系（如蓝色产品 + 冷灰桌面） | 分割边界糊，无干净边缘 |

**只要有 1~2 项命中，就应该停下来向用户提替代方案**（用 AskUserQuestion 给三条路）：

1. **请客户提供纯色底（白底）素材 —— 效果最佳，优先推荐**
   客户手上有实物，重拍/重抠的成本比你在脏图上挣扎低得多。
2. **改用"卡片式陈列"** —— 不抠图，把实拍图裁成产品图卡（见下）
3. 硬抠（明确告知会有脏边，客户接受再干）

> 本项目实测：客户首批 6 张全部命中"木地板 + 手入镜"，且部分横躺。
> 提了替代方案后客户先选了卡片式（作为过渡），随后**自行重新抠好了 5 张白底素材**，
> 最终用真抠图效果明显优于卡片。**「先提方案，让客户去补素材」是性价比最高的路径。**

### ★★★ 坑 5j：白底素材的抠图，**别用阈值** —— 会抠穿产品内部的白色

拿到白底素材后最容易犯的错：`白色 -> 透明`。**这在产品自身有白色部件时是灾难**：

| 本项目实例 | 阈值法的后果 |
|---|---|
| **面漆桶（白桶）** | 桶身整片变透明 -> 桶成了镂空的 |
| **白色空桶** | 同上 |
| **白色滚筒刷头** | 刷头消失，只剩金属杆和手柄 |
| **白色手套包装** | 包装变透明，只剩内部手套 |

**正解 = 连通域漫水填充（4 步）**：只去"与画面外边连通的背景"，内部白色被产品轮廓包围，自然保留。

```python
rgb  = cv2.cvtColor(bgr, cv2.COLOR_BGR2RGB).astype(np.float32)
# ① 背景色 = 四条边的【中位数】（比四角稳，不受角落杂物影响）
bg   = np.median(np.concatenate([rgb[:k].reshape(-1,3), rgb[-k:].reshape(-1,3),
                                 rgb[:,:k].reshape(-1,3), rgb[:,-k:].reshape(-1,3)]), axis=0)
# ② 候选背景 = 颜色接近背景色，且【不是强边缘】（边缘当"墙"，防从轮廓渗进内部）
cand = (np.sqrt(((rgb-bg)**2).sum(2)) < 30).astype(np.uint8)
edges = cv2.dilate(cv2.Canny(cv2.cvtColor(bgr, cv2.COLOR_BGR2GRAY), 40, 120),
                   np.ones((3,3), np.uint8))
cand[edges > 0] = 0
# ③ ★ 连通域过滤：只保留与画面四条外边连通的那部分候选背景
n, lab = cv2.connectedComponents(cand, connectivity=8)
border = set(np.unique(np.concatenate([lab[0,:], lab[-1,:], lab[:,0], lab[:,-1]]))) - {0}
alpha  = np.where(np.isin(lab, list(border)), 0, 255).astype(np.uint8)
# ④ 收缩 + 羽化：去白边残留、消锯齿
alpha = cv2.erode(alpha, np.ones((3,3), np.uint8))
alpha = cv2.GaussianBlur(alpha, (0,0), 1.6)
```

实测：白桶 / 白刷头 / 空手套包装 **全部无穿透**，边缘平顺。
**白底、黄底、任意纯色底都能处理**（改的是 `bg` 和阈值，方法不变）。

**⚠️ cv2 的中文路径坑（第二次踩）**：`cv2.imread` / `cv2.imwrite` 在中文路径下**静默失败**
（读返回 None、写不落盘，不报错）。必须绕开：

```python
def imread_u(p):                       # 读
    return cv2.imdecode(np.fromfile(p, dtype=np.uint8), cv2.IMREAD_COLOR)
def imwrite_u(p, bgr):                 # 写
    ok, buf = cv2.imencode(os.path.splitext(p)[1] or ".png", bgr); buf.tofile(p)
```

### ★★ 透明产品要"落地"：用**产品自身 alpha** 做贴合形状的投影

透明抠图产品直接贴上去会"飘"。用椭圆投影又不贴合不规则外形。
正解：**拿产品自己的 alpha 层做偏移 + 模糊 + 压暗** —— 投影形状自动贴合。

```python
def _drop_layer(key, sprite, dy, alpha, blur):     # ★ 必须按 素材键+参数 缓存
    a = sprite.getchannel("A").point(lambda v: int(v*alpha/255))
    g = Image.new("L", (sprite.width+blur*6, sprite.height+blur*6), 0)
    g.paste(a, (blur*3, blur*3))
    g = g.filter(ImageFilter.GaussianBlur(blur))
    sh = Image.new("RGBA", g.size, (10, 34, 64, 0)); sh.putalpha(g)
    return sh, blur*3

def put_sh(im, sprite, cx, by, key, alpha=1.0, dy=0.0, rot=0.0, sh_dy=16, sh_a=95, sh_blur=20):
    s = sprite.rotate(rot, resample=Image.BICUBIC, expand=True, fillcolor=(0,0,0,0)) if rot else sprite
    sx, sy = int(cx-s.width/2), int(by-s.height+dy)
    sh, pad = _drop_layer(key, s, sh_dy, int(sh_a*alpha), sh_blur)
    im.alpha_composite(sh, (sx-pad, sy-pad+sh_dy))
    im.alpha_composite(_with_alpha(s, alpha) if alpha < .999 else s, (sx, sy))
```

**⚠️ 缓存不是可选项**：投影要 `GaussianBlur`，不缓存则每帧都算，
实测重渲 159 帧从 **147s 拖到 333s（2.3 倍）**。
缓存键**不能用 `id(sprite)`**（id 会被回收重用导致错图）——用 `(素材名, 高度, 参数)`。

### ★★ 卡片式陈列（实拍图 -> 产品卡）的完整做法

**关键不是"裁一下"，而是"让实拍图不脏"**。四步：

```python
def card(name, h, radius=20, pad=9, bw=6):
    im = Image.open(path).convert("RGB")
    # ① 降饱和 + 提亮 —— 实拍的地板/桌面杂色是主要"脏源"
    a = np.asarray(im).astype(np.float32)
    g = a @ np.array([0.299, 0.587, 0.114], dtype=np.float32)
    a = g[..., None] * 0.62 + a * 0.38            # 饱和度降到 0.38

    im = Image.fromarray(a.astype(np.uint8))
    # ② 四角径向压暗 —— 视觉聚焦到产品
    iw0, ih0 = im.size
    vg = Image.new("L", (iw0, ih0), 0)

    vg = vg.filter(ImageFilter.GaussianBlur(int(iw0*0.16)))
    im = Image.composite(im, Image.blend(im, Image.new("RGB",(iw0,ih0),(86,112,146)), 0.30), vg)
    # ③ 白边圆角 + 细描边（图片自身也要圆角遮罩）
    # ④ 投影用 rounded_rectangle + GaussianBlur，按 (w,h,alpha) 缓存
```

**① 降饱和是关键一步** —— 不做这步，实拍的暖棕色会和 3D 卡通的卡通色打架，
摆上去像"贴了几张脏图"。做了之后卡片与背景调性立刻协调。

**裁切框必须逐个手工定**（`(l,t,r,b)` 按比例），避开：手、桌面杂物、家具边缘。
横躺拍摄的素材要**收成近方比例**，否则卡片宽度会占满画幅。

### ★★ 卡片环的版式与断言：主体要"让位"，且四向都要查

要"围着主体摆 N 张卡"时，**主体必须先缩小让出环形空间**：
本项目把主产品桶从高 760 缩到 **600**，居中偏上，才腾出左/右/下的环状位置。

```python
for nm, cxx, cyy, chh, _dd, _rot in CARDS:
    lay = card(nm, chh)
    cx0, cx1 = cxx - lay.width//2, cxx + lay.width//2
    cy0, cy1 = cyy - lay.height//2, cyy + lay.height//2
    ck(cx0 >= 8 and cx1 <= W-8,  "...出画左右")
    ck(cy0 >= 8,                "...出画顶")
    ck(cy1 + 6 <= SUB_CY-46,    "...压字幕")     # 底边必须单独查
    ck(not 相交(cx0,cx1,cy0,cy1, 主桶框), "...压主产品")
    ck(not 相交(cx0,cx1,cy0,cy1, 角色框), "...压角色")
```

**四向都要查**（出画左/右/上/下 + 压主桶 + 压角色 + 压字幕）。
本项目扩断言后**抓到 3 处目检没发现的冲突**（一张卡右缘出画且压主桶、一张卡左缘出画）。

本项目初版 `i*0.075` 导致 2.6s 就全出完、后面 2.3s 画面静止（复现坑 5f）。

### ★★ 改文案前，先把「时长变化」交给用户定

本次把一句 27 字的旁白改成 59 字，**总长 32.0s → 37.9s（+18%）**。
39 秒对信息流短视频是另一个量级，**不能替用户默认接受**。

先按"字符数等比"估出新时长（用当前段实测旁白时长 × 新字数/原字数），
再用 AskUserQuestion 给三个选项：
**按原话改 / 压缩改写保信息 / 砍信息保原时长**。

### ★★ 坑 4：终态必须"有内容"

### 示意图的通用骨架

```python
gold = ((r>200)&(g>150)&(g<225)&(b<130)).mean()
# 段落边界确有切换
da = |frame(tb-0.2) - frame(tb+0.2)|.mean()   →  > 3.0
# 音频真的有声音、且未削顶
ffmpeg -af volumedetect  →  mean > -40dB 且 max < 0dB
# 双画幅内容一致（主色调接近）
```

### ★ 坑 8：合规判据别太粗 —— 「第一」要区分序数词

```python
# ✗ 纯子串匹配会把「第一步」「第一道屏障」判成违禁词
# ✓
if re.search(r"第一(?!步|道|次|层|个|遍|时间|批|阶段|年|周)", text):
    hits.append("第一")
```
广告法禁的是**排名性宣称**（第一品牌/销量第一），不是序数词。

### ★★ 坑 8b：词表必须含「绝对化用语变体」，且扫描正则**禁止跨行**

**两个都真踩过（2026-10-15，某防水品牌A招商短片返工：成片带「极致」交付，被迫整片重做）。**

**① 词表只列了"业务词"，一个绝对化用语变体都没有。**

原表的禁用词是 `十年不漏 / 5-8平方 / 3-5毫米 / 手机号 / 保证不漏 / 永久 / 终身 / 扫码`——
**于是「极致」一路通过核验、留进了成片**（是客户明确要求写入的表述，无人提示风险）。
补入变体后，断言数 **81 → 94**：

```python
BAN_WORDS = [ ...业务禁用词... ,
    # ★ 绝对化用语变体（原表缺失 → 导致「极致」漏检）
    "极致", "顶级", "最优", "最佳", "唯一", "首个", "首选",
    "绝对", "彻底", "完全", "包不漏", "国家级", "世界级",
]
# 注：「最」「第一」**刻意不列入本表** —— 见坑 8，它们需带序数词排除。
#     要用必须写成 regex（`第一(?!步|道|…)`），绝不能直接 substring。
```

**② 扫描正则必须禁止跨行，否则会把代码注释也扫进去。**

原正则 `r'"([^"\\]*[\u4e00-\u9fff][^"\\]*)"'` 里的 `[^"\\]*` **可以匹配换行**，
会把**跨多行的代码段整段捕获**，连带把**注释里的中文**算进扫描范围。
实测后果：补表后立刻误报「**完全**」命中 1 次 —— 追查发现它只出现在
`render.py` 的注释里（`# 右侧：卖点文字（三行 —— 与配音/字幕完全一致）`）。

```python
# ✗ 可跨行 → 把注释里的中文也算进去
re.finditer(r'"([^"\\]*[\u4e00-\u9fff][^"\\]*)"', src)
# ✓ 不允许换行 → 只取单行字符串字面量
re.finditer(r'"([^"\\\n]*[\u4e00-\u9fff][^"\\\n]*)"', src)
```

**⇒ 纪律：动禁用词表之前，先确认「正则的实际扫描范围」＝「你以为的扫描范围」。**
否则新增的词会立刻制造一堆假失败，把真问题淹掉 —— 这与坑 8 是同一类病：
**判据本身要先被质疑。**

### ★ 中文路径坑

`cv2.imread` / `cv2.VideoCapture` 对中文路径**不可靠**。
一律先用 ffmpeg 抽帧成 PNG，再用 Pillow 读（Pillow 对中文路径无问题）：

```python
subprocess.run([FF, "-y", "-ss", f"{t:.3f}", "-i", video, "-frames:v", "1", out])
```

## 七、标准工程结构

```
<build>/_<proj>_video/
  make_vo.py          分段 TTS + 时间轴标定 → timeline.json / vo_full.wav
  test_rate.py        标定 rate→时长曲线（避免盲试语速）

  encode.py           H.264 编码 + 旁白/BGM 混音
```

**`timeline.json` 是唯一数据源**：段起止、旁白时长、字幕文本全在里面，
渲染与核验都从它读。改文案后固定顺序：
`make_vo.py` → `render.py all v` → `render.py all h` → `encode.py` → `verify_video.py`

### `render.py` 建议内置 `preview` 模式

每段取 0.45/0.9 两个时刻各渲一帧，拼成横条 —— **改版式时看它比看视频快 100 倍**。
本次靠它揪出了：片尾标题压四字进度、示意图终态留空、横版要点卡压角色 三个问题。

## 八、本机环境备忘

- `edge_tts` 需自行安装：`pip install edge-tts`（实测 7.2.8 可用）
- `imageio_ffmpeg 0.6.0` 自带 ffmpeg 7.1（libx264 / aac / libmp3lame 齐全）
- Pillow 10.4 / numpy / scipy / cv2 5.0 可用；**无 moviepy**
- 中文字体（**只许 OFL**）：`Noto Sans SC Bold (TrueType).otf`（粗）/ `Noto Sans SC (TrueType).otf`（常规）
  ⇒ 工作目录内建议复制为 `noto-bold.otf` / `noto.otf`，用相对路径调用（避开空格与括号）
> ⛔ **字体授权硬规则（2026-10-17 起）**：中文字体**只许用 SIL OFL 授权的** —— `Noto Sans SC` / `Noto Sans SC Bold` / `Noto Serif SC` / `思源宋体` / `思源黑体`。
> **禁止**使用**微软雅黑、中易黑体、中易宋体、等线（Deng）、楷体、仿宋**等**非免费商用**字体
> —— 收费产品中把字形渲染进成片属高风险；**按字体名称判定，不看文件名**。
> 路径含空格/括号时，**复制到工作目录并命名为 `noto.otf` / `noto-bold.otf`**，用相对路径调用。
