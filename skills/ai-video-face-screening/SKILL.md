# 视频「无面孔」筛查（双判据）

## 0 先把判据说死

**PASS ＝ ① 逐帧采样「人脸命中 = 0」　且　② 导出关键帧「逐张目检无面孔」。两项都过才算过。**

- ⚠️ 只跑检测器报"0 命中"**不构成 PASS** —— 逆光、暗部、背影、侧脸都会造成 DNN **假阴性**。
- ⚠️ 检测器报命中**也必须人工看图** —— 衣物褶皱、窗格、桌面边缘上常见**假阳性**。
- ⭐⭐ **高置信 ≠ 真脸**：实测 **后脑发髻／耳廓＋颊缘**可被判 **0.80**（S1 台灯桌面 0.51、S2 握手机的手 0.51–0.59、S3 后脑耳侧 0.56–0.80，**全部误报**）。
  只看置信度会得出"有脸"的**反向错误结论**，比漏检更危险。
  **补一步判据：把检测框画到帧上、裁到框周边并放大到能看清眼鼻口**，才能区分"真脸"与"耳侧误报"。
- ⚠️ 结论要写成"采样 N 帧 0 命中 ＋ M/M 关键帧目检无面孔"，**不要**写成"全片无脸"（采样不是全帧）。

## 1 环境探测（先做，别猜）

```bash

PY="$(python3 tools/env_probe.py --print python)"
"$PY" -c "

import os; print('haar dir =', cv2.data.haarcascades, os.listdir(cv2.data.haarcascades))
"
```

**本机实测结果（2026-09-26）**：

| 项 | 值 | 含义 |
|---|---|---|
| `cv2` | **5.0.0**（`opencv-python-headless 5.0.0.93`） | 与 4.x 的 API **不兼容** |
| `cv2.CascadeClassifier` | ❌ **不存在** | 5.0 已移除；`from cv2 import objdetect` 也失败 |

| `cv2.FaceDetectorYN` | ✅ 可用 | **唯一可行的人脸检测器**（DNN，需外部 onnx） |
| `imageio_ffmpeg` / `PIL` / `numpy` | ✅ 可用 | 抽帧与拼图备用 |

⭐ **教训：判断"某资源可用"必须 listdir/实测，不能只看路径存在。**

## 2 取 YuNet 模型

```bash
URL="https://github.com/opencv/opencv_zoo/raw/main/models/face_detection_yunet/face_detection_yunet_2023mar.onnx"
curl -sSL --max-time 90 -o _yunet_2023mar.onnx "$URL"
stat -c %s _yunet_2023mar.onnx         # 期望 232589 B
head -c 8 _yunet_2023mar.onnx | od -c  # 期望以 \b 006 \022 \a p y t o 开头（ONNX/pytorch producer）
```

**校验点**：体积 **232,589 B**；头部字节 `0x08 06`（ir_version）＋ `0x12 07 "pytor"`。对不上就是没下全。

## 3 ⭐⭐ 中文路径 —— 本机最大的坑

**OpenCV 的 C++ 层读不了非 ASCII 路径**，而且 **两处同时中招**：

| 中招处 | 症状 |
|---|---|
| `cv2.VideoCapture(path)` | 打不开 / 静默返回空帧 |
| ONNX 加载（`FaceDetectorYN.create`） | 报 `Can't read ONNX file: …` |
| `cv2.imwrite(path)` | 静默失败 |

**对策三条**：

1. 视频先 `shutil.copyfile` 到 **ASCII 临时目录**（`tempfile.gettempdir()`）再解码；
2. 模型 likewise（脚本已内置 `if not model.isascii(): copy to tmp`）**或**模型放 ASCII 路径；
3. 写图 **不要用 `cv2.imwrite`**，改用：
   ```python
   ok, buf = cv2.imencode(".png", frame)
   open(out_path, "wb").write(buf.tobytes())
   ```

⭐⭐ **归因次序**：报 `Can't read ONNX file` 时，**先换 ASCII 路径复测，再怀疑模型文件损坏**。本次实测就是纯路径问题，模型完好。

## 4 跑筛查

用本技能自带脚本（无需 ffmpeg）：

```bash
cd "<视频所在目录>"
"$PY" scripts/frames_facecheck.py "<视频>" "<输出目录>" --save 8 --model "<yunet.onnx>"
```

脚本做三件事：读参数 → 每 0.25 s 采样跑 YuNet（阈值 0.5，NMS 0.3）统计命中 → 均匀导出 N 张关键帧。

## 5 ⭐ 接触表：一次看完所有关键帧

逐张 Read 图片很费上下文。把 N 帧拼成**一张接触表**，**一次读完**：

```python
from PIL import Image, ImageDraw
import os, glob
fs = sorted(glob.glob("_frames/*.png"))
TW, TH, cols = 480, 270, 4
rows = (len(fs)+cols-1)//cols
sheet = Image.new("RGB", (TW*cols, (TH+18)*rows), (18,18,18))
dr = ImageDraw.Draw(sheet)
for i, f in enumerate(fs):
    r, c = divmod(i, cols)
    sheet.paste(Image.open(f).convert("RGB").resize((TW,TH), Image.LANCZOS), (c*TW, r*(TH+18)))
    dr.text((c*TW+6, r*(TH+18)+TH+3), os.path.basename(f)[:-4], fill=(220,220,220))
sheet.save("_contact.png")
```

⭐ 好处：**不漏帧**（比抽样看 3 张更可靠），且 8 帧只花 1 次读图。

## 6 交付时的口径（写给客户/内部）

- 结论写成：**"YuNet 每 0.25 s 采样 N 帧命中 0 处 ＋ 导出 M/M 关键帧目检无面孔 → PASS"**。
- **附取证**：关键帧 PNG 目录 ＋ 接触表 ＋ 视频参数（时长/帧率/分辨率/体积/哈希）。
- ⚠️ **保留人工目检这一步的说明** —— 只报机器结果会被质疑"暗部假阴性"。
- ⚠️ 若视频要对外投放，**机器筛查 ≠ 深度合成标识义务**；标识（画面＋元数据）是另一件事。注意部分生成器已**自带**水印（如"视频由AI生成"），仍可能需叠加自有标识。

## 6.5 ⭐⭐ 预防胜于筛查：要"**结构上排除**"，不要"**要求做模糊**"

实测（2026-09-26）：镜前人物那镜，提示词写了「镜中的倒影是**失焦的、看不清五官**的模糊轮廓」——
模型**完全无视**，镜中给出**清晰的男性正脸**（YuNet **21/21 帧命中、最高 0.87**）。

✅ 改法不是加强语气，而是**改结构**：

- 提示词改成「镜子里只映出**空房间、窗和光**，**镜中没有任何人**」；
- 人物退到**前景背影**（背对镜头）；
- 把失败形态钉进 `negative_prompt`：`镜中的人, 镜子里的脸, 倒影中的人, 镜中的身影, 正脸, 人脸, 五官…`。

重拍后 **21 帧 0 命中**。

⭐ **通则**：凡「不许出现 X」的约束，**不要靠"弱化 X"（模糊／失焦／遮挡／只给侧面）** —— 那是模型爱忽视的软要求；
**要靠"结构上让 X 无处可生"**（改构图、改朝向、改场景元素），再把失败形态写进 negative_prompt。

⚠️ 同理：**"0 命中"必须是「机器筛查 ＋ 人工目检」双判据**，别把模型的自我描述当事实。

### 6.6 ⭐⭐ YuNet 的系统性盲区：**画框边缘的半张脸／侧脸抓不住**（2026-09-27 静帧实测）

对 9 张文生**图**逐一筛查，**3 张 YuNet 报 0 命中、目检却清楚有脸**，漏检形态完全一致：

| 静帧 | 目检所见 | YuNet |
|---|---|---|
| 会议室 | **画框左缘**女性侧脸（鼻唇可见）＋**右缘**男性面部（眼鼻嘴可见，均被取景切掉一半） | **0 命中** |
| 浴室 | 女性**完整侧脸**（鼻、唇、下颌、耳廓、眉弓都清晰） | **0 命中** |
| 咖啡吧台 | 主体背对，但**吧台后店员的半张脸**（鼻唇下颌）探进画面 | **0 命中** |

⭐ **规律**：YuNet 对**完整正脸**很稳；对**被画框切掉一部分的脸／纯侧面脸**系统性漏检。
而文生图最爱把"路人"塞进画面边缘 —— **这正是最容易被漏检的位置**。

**目检纪律：先扫四条边和背景，再扫主体。** 别从画面中心看起。

**结构性写法（对静帧同样有效，已实测）**：
- ✅ 有效：**正上方俯拍**（头部几何上无法入画）／**只框双手**／**画面里只出现一个背对者**（写明"没有任何其他人物"）／镜中映**空房间**。
- ❌ 无效：只写「看不到任何人的脸」—— 模型仍会往画面边缘加旁人（会议室 v1 就是这么来的）。
- ⭐ **逐张生成后立即筛查＋目检，命中即重拍**；不要攒一批再查（攒批会一次废多张）。

**反向也成立（假阳性）**：杯中茶色被判 0.53（画框目检＝茶杯）。**命中处必须画框放大看**，双向都要人工裁决。

### 6.7 ⭐⭐ 「命中数」与「真有脸」几乎没有相关性（2026-09-27 真片逐帧实测）

对 9 段 AI 生成**视频**逐帧扫描（每段 121 帧，720×1280），结果非常反直觉：

| 段落 | YuNet 命中 | 目检真脸 | 命中框落在哪 |
|---|---|---|---|
| 咖啡店背影 | 22/121 帧，最高 0.64 | ☠️ **有**（左缘被切掉的侧脸） | 左缘半张脸（box x=2~8） |
| 会议室俯拍 | 15 帧，最高 0.77 | 无 | **握拳的手背**、**空桌面＋纸张** |
| 浴室镜前 | 3 帧，最高 0.67 | 无 | **指尖／指甲** |
| 写日记 | 6 帧，最高 0.58 | 无 | **茶杯＋蒸汽** |
| 吧台背影（重拍版） | **106/121 帧**，最高 0.79 | 无 | **握拳的手**（几乎每帧都命中） |
| 桌面两杯 | 40 帧，最高 0.69 | 无 | **杯与碟、虚化背景的器皿、窗景光斑** |
| 双手交叠 | 37 帧，最高 0.80 | 无 | **咖啡杯与碟** |
| 抽象光 / 深夜手机 | **0 帧** | 无 | — |

⭐⭐ **两侧极端同时出现**：
- **真脸可能只值 0.64、且只在 22 帧里出现**（切边侧脸）；
- **纯假阳性可以刷到 106/121 帧、最高 0.79**（一只拳头）。

⇒ **绝不能**用"命中数多少""置信度高低"当放行判据。**只有画框放大目检才算判据。**

⭐ **假阳性来源（本轮新增，供目检时优先怀疑）**：**握拳的手／手背指关节**、**衣物褶皱（西装袖子）**、
**杯碟边缘与液面**、**虚化背景的器皿/光斑**、指尖与指甲。
⭐ **反直觉的一点**：画面**越干净**（纯俯拍桌面、只有手）越容易出**大量假阳性** —— 因为检测器在找"类脸纹理"，
而平铺的桌椅/杯碟给足了这种纹理。

⚠️ **视频要逐帧，不要抽样**：切边脸与侧脸可能只在一小段帧里出现（本案 22/121 帧 ≈ 0.9 s）。
抽样（如每秒 1 帧）刚好可能整段跳过。逐帧成本极低（121 帧/5 s 秒级完成）。

### 6.8 ⭐ 生成阶段的「非脸部」内容红线也要用同一套办法

本轮另一条**非人脸**的废件：一段"吧台背影"提示词产出了**裸肩＋明显内衣肩带**的女性背影特写 ——
品牌片不宜，且与提示词要求的"肩·后背·抬起的手"不符。

**处理同 §6.5**：不靠"要求穿得保守"，而是
① 提示词写死**具体服装**（"wearing a light beige knit cardigan with long sleeves that **fully covers** her back and shoulders"）；
② negative_prompt 钉死裸/透视/内衣类失败形态（`bare shoulder` / `bare back` / `backless` / `bra strap` / `underwear` / `lingerie` / `naked` …）；
③ 重拍后目检通过（本次 106 帧命中**全为拳头的假阳性**，画面着装合格）。

⭐ 通则：**"不许出现 X"里的 X 不限于脸** —— 裸露、伤痕、烟酒、真实品牌标识、可读文字，都用同一套
「写死具体形态 ＋ 负面词钉死 ＋ 重拍后目检」的办法。

### 6.9 ⭐⭐ 同一批帧「重新取景／放大」后，**红线必须重测**——置信度会系统性抬高（2026-09-30 实测）

从已过检的竖版成片（1080×1920）**裁切**出 16:9 横版（`crop=720×405 → scale=1920×1080`，放大 **2.67×**）后的重测对比：

| 版本 | 分辨率 | 命中 | 最高置信度 | 目检真脸 |
|---|---|---|---|---|
| 竖版（原片） | 1080×1920 | 224 帧 / 276 处 | 0.83 | 0 |
| **横版（同帧裁切放大）** | 1920×1080 | **132 帧 / 184 处** | **0.84** | 0 |

⭐⭐ **关键：这是同一批帧，画面内容一模一样，只是被裁切放大了。**
⇒ **裁切放大 → 原本是小块纹理的手部假阳性 → 变得更大更"像脸" → 置信度抬升**（0.83→0.84，且高分段更集中）。

**纪律**：
1. **不能写"内容同源，故沿用原片结论"** —— 必须**对新文件重跑逐帧筛查**（成本极低，几秒到几分钟）。
2. 放大倍数越大，假阳性越"像" → **放大版的高命中数不是异常，是预期**，仍然只能靠**逐框目检**定判。
3. 本案例 132 个命中帧**全部**为假阳性：**握杯的手／拳（占多数）**、手掌、杯碟边缘、衣袖、抽象光条。
   一个都没漏检真脸 —— 印证 §6.7「命中数与真有脸几乎无关」。

## 7 常见误判清单

| 现象 | 真因 | 处理 |
|---|---|---|
| `module 'cv2' has no attribute 'CascadeClassifier'` | OpenCV 5.0 移除该类 | 换 YuNet |
| `cv2.data.haarcascades` 里没有 xml | 5.0 不分发 XML | 换 YuNet，别去"找 XML" |
| `Can't read ONNX file` | **中文路径**（多数情况） | 换 ASCII 路径复测 |
| `cv2.imwrite` 返回 False 且无异常 | 中文路径 | 改 `imencode` + `open(...,'wb')` |
| `detect()` 返回 `(retval, None)` | 该帧无脸（**正常**） | 判空即 0，别当报错 |
| 视频明显有人却 0 命中 | 逆光/背影/暗部假阴性 | 必须人工目检，不得据此下结论 |
| **画面边缘的半张脸/侧脸 0 命中** | YuNet 对被取景切掉的脸与纯侧脸**系统性漏检** | 目检**先扫四条边**；静帧预防＝俯拍/只框手/只一个背对者 |
| **后脑/耳侧被判 0.7–0.8** | 检测器把"耳＋颊缘"当脸（**误报**） | 画框 + 放大到能看清眼鼻口再判 |
| **空景（台灯/桌面/窗格）被判 0.5** | 小模型对几何纹理误报 | 同上；画面无人时优先判为误报 |
| **命中 106/121 帧却无脸** | 画面里**一只握拳的手**被反复判为脸 | **命中数不是判据**；逐帧命中越多越要警惕是同一处假阳性在刷数 |
| **干净画面反而命中一堆** | 平铺桌椅/杯碟/液面给出"类脸纹理" | 先怀疑**杯碟/液面/虚化背景器皿/光斑**，画框放大定位 |
| **切边脸只出现 22/121 帧** | 侧脸只在人物转头的一小段里可见 | **必须逐帧**，不能按秒抽样（抽样会整段跳过） |
| **视频规格与要求不符但参数传对了** | 生成器**静默忽略**画幅参数（本案 Pika v2.2 传 `9:16` 仍出 1280×720） | 出片后**读真实像素**（ffmpeg stderr 的 `Stream #`），别信"我传了参数" |
| **裁切/放大后命中数变了、置信度更高** | **放大让手部假阳性更像脸**（0.83→0.84） | **重跑筛查**；不得以"内容同源"沿用原结论（§6.9） |
