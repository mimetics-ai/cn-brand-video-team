# 生成式镜头制作（生成档）

> 一句话定位：**实拍拿不到的镜头才走这条轨**。默认仍走实拍/截图轨（`real-footage-product-video` / `screenshot-explainer-video`）——
> 触发本 skill 的条件只有一个：客户要的画面在现实中拍不到（不存在的场景、AI 真人出镜、要求"全程全动态"）。
>
> 来源：2026-11 三起重实际战的完整复盘。每一条判据背后都有一个具体的返工，不是理论推演。

## 0 开工前先读这四条坑（每条都踩过）

1. **静图 zoom/pan 不等于"全动态"**。把一张图 zoom in，帧间差实测只有 **3–7**，观众看着就是"一张会动的图"。
   客户说"整个画面都应该是动态的"时，必须走 t2v/i2v 直出（帧间差 **17–94**），不能用静图加 Ken Burns 糊弄。
2. **落版类 RGBA 层禁用 `fade=t=in`**。实测 `fade` 会吞掉 alpha 通道，导致彩色 logo/字卡元素隐形——
   而且**自检脚本不报**（文件存在、时长对、帧数对，就是看不见）。正解：直接 `overlay`，不跟 fade。
3. **左上角"AI生成"方框是烧录水印，delogo 会留糊块**。正解是裁切法（见 §3）。
4. **镜头顺序不能按文件名时间戳猜**。实测生成任务返回的文件按时间戳排序 ≠ 分镜顺序，
   hero 顶光独照镜曾因此错到片头。必须显式写"镜号→文件名"映射表（见 §4）。

## 1 生成档入口分诊（主理人 Phase 1.5b 调用）

| 客户要什么 | 走哪条轨 |
|---|---|
| 有实拍素材／产品图，只要求剪出成片 | ❌ 不走本轨 → `real-footage-product-video` |
| 有界面截图，要做讲解视频 | ❌ 不走本轨 → `screenshot-explainer-video` |
| 素材里有真实文字（品牌名/型号/净重），要求"正品" | ❌ **禁用生成式**（AI 一改就是假字）|
| 要"不存在的场景"（如全场灯灭顶光独照＋人群剪影） | ✅ 本轨 |
| 要 AI 真人/AI 美女出镜 | ✅ 本轨（先过角色卡＋合规闸，见 §5）|
| 明确要求"全程全动态" | ✅ 本轨，且必须 t2v/i2v 直出（§2）|
| 要跨镜同一个人物 | ✅ 本轨，但必须定妆帧锚点（§4）＋如实声明能力边界（§5）|

**分诊输出**：写一行 `生成档：是/否 + 理由 + 预计 credits 区间`，附在立项侦察件里。

## 2 真动态判据（验收核心）

### 2.1 帧间差分级（用实测数字说话，不靠"看着动"）

抽相邻两帧算 RGB 逐像素平均差（frame difference），分级判据：

| 帧间差区间 | 判读 | 处置 |
|---|---|---|
| **17–94** | 真动态（i2v/t2v 直出） | ✅ PASS |
| **8–17** | 弱动态，边缘情况 | 人工看 3 帧确认是否有实质运动 |
| **3–7** | 静图 zoom/pan | ❌ FAIL"全动态"要求；除非该镜明确设计为定格 |
| **<3** | 几乎静止 | 戏剧定格凝视镜可 PASS，但须显式标注例外 |

**戏剧定格例外**：实测顶光独照镜帧间差 **4.37**，是"全场灯灭、一束顶光照下"的凝视定格——
这类镜头**合理但必须标注**，不能默认按"没动"判失败，也不能拿它冒充"全动态镜"。
交付说明里写：「第 08 镜帧间差 4.37，为戏剧定格凝视，非动态镜；其余 7 镜 17–39 为真动态」。

### 2.2 抽帧测量脚本要点

- 用 ffmpeg 抽帧到纯 ASCII 目录（本机中文路径会踩坑，见实拍 skill 同源规则）
- 逐对相邻帧算 `np.abs(frame[i].astype(int) - frame[i+1].astype(int)).mean()`
- 输出每镜的 min/median/max 帧间差，附到交付说明

## 3 AI 水印处理（三类分开，别混）

| 水印类型 | 位置 | 处理方式 |
|---|---|---|
| **我方叠加层** | 右下角「AI 生成·WORKBUDDY」 | 生成透明层即去（本来就是 `make_ai()` 叠的），重出成片即净 |
| **生成素材烧录** | 左上角「AI生成」方框 | **裁切法**（下方命令），delogo 留糊块不可用 |
| **容器隐式标识** | metadata comment / AIGC / AI-Generated | **保留**，画面不可见，是合规标识的一部分 |

### 3.1 烧录水印裁切法（标准命令）

生成素材水印位置实测一致：`x∈[10,80], y∈[18,52]`（左上）。统一处理：

```bash
# 每个镜头先 scale 到 1920 宽，再裁掉左上水印区，再拉回 1920x1080
-vf "scale=1920:1080:force_original_aspect_ratio=increase,crop=1920:1080,setsar=1,\
crop=1820:1010:100:70,scale=1920:1080,setsar=1,fps=24,format=yuv420p"
```

- `crop=1820:1010:100:70`：从 (100,70) 起裁 1820×1010，把左上角 x<100、y<70 的水印整体切出画面
- 画面放大约 5%，可接受
- 右下角我方叠加层若也在，同轮生成透明层去掉

### 3.2 验收

- 抽 6 帧盲检：左上角无方框、无糊块、无残留
- 容器 metadata 保留：`AI-Generated=1`、`AIGC=1`、`comment=部分画面由AI生成`
- 图像查看工具对相似抽帧会去重误判 unchanged → 改用**像素级亮度对比＋并排图**确认（实踩）

## 4 一致性与镜头映射（防换脸、防错位）

### 4.1 定妆帧锚点

1. 先生成**首张人物定妆帧**（角色卡＋ prompt 固化：东亚女性、黑发、克制优雅、深色得体服装）
2. 后续每张关键帧用 i2i：`image1` = 定妆帧，参数 `input_fidelity: high`
3. 每张关键帧的 prompt 只改"动作/光线/构图"，人物描述段**逐字不变**

> 头部平台已提供多参考锚点（`ae_nano_banana_2_1` 支持 14 张参考图、`ae_pulid` 人脸锁），
> 有则必用；没有则用上述"定妆帧＋input_fidelity"土法，效果略逊但可控。

### 4.2 显式镜头语义映射（硬闸）

**严禁**按生成文件的时间戳/字典序推断镜头顺序。必须在 `_prepare_shots.py` 里显式写：

```python
SHOTS = [
    ("01", "人群熙攘",   ".../07-22-45.mp4"),
    ("02", "她从中间走过",".../07-25-40.mp4"),
    # ...
    ("08", "全场顶光独照",".../07-42-13.mp4"),   # hero 镜必须手动钉死
]
```

- 映射表作为中间产物落盘，检查点 A 检查"映射表存在且每镜各有对应文件"
- 实踩：不写映射表时，顶光独照 hero 镜被错排到片头，全片叙事崩塌

## 5 合规与能力边界（红线不可越）

1. **擦边规避**：涉及人物的广告片，旁白第 5 句这类位置要主动把焦点从身体移到气场
   （如"被看见的从来不是衣服，是那份不慌不忙"）——把擦边读法掐灭在文案层。
2. **三条红线不变**：不承诺院线质感、不承诺真人级微表情、不承诺跨集同脸。
   生成式能力变强 ≠ 可以拔高对外承诺。触发即干预（>3min／强剧情多角色／高难物理交互）纪律照旧。
3. **AI 标识双层**：画面烧录水印按 §3 处理，容器 metadata 保留，交付说明写明"部分画面由 AI 生成"。
4. **真实文字禁生成**：素材/画面里有品牌名、型号、净重、批号时，禁用生成式——AI 一改就是假字（与实拍轨同源纪律）。
